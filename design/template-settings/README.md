# Handoff: Template Settings View

## Overview
Per-project template customization per REQ-010 / DEC-023: a **Templates**
view where the user browses every document type, sees the template new
documents of that type start from, edits it in the same CodeMirror 6
editor surface the app already ships (WO-022), and resets a customized
type back to the built-in default. The view is a thin surface over the
files at `veri/templates/<type>.md` — saving writes the file, an outside
edit shows up live, and there is no second store (DEC-002).

## About the Design Files
`template-settings.html` is a **self-contained interactive prototype**
(open in a browser) showing look and behavior on illustrative content.
It is a design reference, not production code — its textarea editor is a
stand-in for the CodeMirror 6 island from the markdown-editor bundle
(DEC-020), which is the engine for the real implementation. All tokens
reuse the canon (`design/README.md`); tab and rail behavior extend the
document-tabs and navigation-model bundles unchanged.

## Fidelity
**High-fidelity for tokens, layout, and interaction rules.** Editor
internals follow the markdown-editor handoff (SRC-008); where this spec
is silent on editor behavior, that spec applies.

## Entry points
- **Icon rail**: a Settings glyph `⚙` after the flex filler, directly
  above the agent-connection button `⌁`. Same 32×32 button anatomy,
  hover, active tint, and instant custom tooltip ("Templates") as every
  rail item. Clicking opens the Templates view as a preview tab
  (document-tabs rules; one instance, closeable).
- **Command palette**: typing `templates` or `settings` surfaces the
  view row (glyph `⚙`, muted `view` badge), like `board` or `home`.

## Layout
Standard shell — 44px topbar, 44px rail, 250px sidebar, 37px tab strip.
The view fills the editor area: max-width 920px, centered, padding
28px 40px 60px.

- **Header**: "Templates" 20px/600 `#E7E4DE`; right-aligned mono meta
  `veri/templates/` 11px `#6E6B76`. Subtitle line 13px `#8B8893`:
  "How new documents start. Edits apply to the next document created —
  existing documents never change."
- Below, a two-pane row (16px gap):
  - **Type list** (210px, fixed): one row per built-in type —
    requirement, decision, work order, source, workflow — in that
    order. Row: 28px, radius 6px, 7px type-color square swatch +
    13px sans label + right-aligned state chip. Workflow uses the
    neutral swatch `#8B8893` (it has no type color in the canon).
    Active row `rgba(232,112,58,0.09)` bg + `#F0A87E` label; hover
    `#1B1B20`.
  - **Editor card** (flex): 1px `#1F1F24` border, radius 9px, bg
    `#131316`, min-height 480px.

## State chips
Mono 10px, radius 4px, padding 2px 7px:
- **default** — `#6E6B76` text, 1px `#26262C` border, no fill. Shown
  when the project file is absent or its content equals the built-in
  default (whitespace-insensitive compare).
- **custom** — ember tint: `rgba(232,112,58,0.1)` bg, `#F0A87E` text.
The same chip appears in the type-list row and the editor card header,
always in sync.

## Editor card
- **Card header** (44px, hairline bottom `#1E1E24`, padding 0 16px):
  mono 11.5px filename `veri/templates/decision.md` in `#A09DA6` +
  state chip; right side: **Reset to default** (bordered secondary
  button, 11px mono, visible only when the chip is `custom`) and the
  save-state text (mono 10.5px: `saved` in `#55525E`, `unsaved — ⌘S`
  in `#D9A03F` when dirty).
- **Frontmatter preview** (below header, padding 14px 16px, dashed
  bottom border `#26262C`): the frontmatter `veri new` will generate,
  rendered as ghost mono 11.5px `#55525E`, non-editable, non-selectable
  as part of the template. Preceded by a one-line label (mono 9.5px
  uppercase, letter-spacing .1em, `#6E6B76`): `⛭ generated by veri —
  not part of the template`. This teaches the REQ-010 boundary: only
  the body is the template. Example content uses placeholder values
  (`id: DEC-0XX`, today's date, initial status for the type).
- **Body editor**: the CM6 surface per SRC-008 tokens (Source Sans 3
  14.5px/1.65 `#C9C6CF` on `#0F0F11`, same syntax palette), padding
  18px 16px, fills the card. The buffer is exactly the template file's
  content — body-only markdown, no frontmatter, so **no guarded
  ranges** apply.

## Editing semantics
Identical to the document editor (SRC-008) wherever applicable:
- Explicit **⌘S** save; dirty state shown by the card-header save text
  and the Templates tab's dirty dot (replacing its ×). Switching types
  with a dirty buffer keeps the buffer (per-type buffers, like
  per-tab buffers); closing the tab with any dirty buffer prompts
  Save all / Discard / Cancel.
- Saving writes `veri/templates/<type>.md` verbatim. Saving when the
  file is absent creates it (the pre-feature-project case); the chip
  recomputes on every save.
- **External changes**: clean buffer → silent reload; dirty buffer →
  the same conflict banner (Reload / Keep mine) as document tabs.
  Deleting the file externally flips the chip to `default` and, if
  clean, reloads the built-in content.
- No `[[` autocomplete (templates should not hard-link real IDs;
  typing `[[` just inserts text).

## Reset to default
Clicking **Reset to default** turns the button into an inline confirm
(same pattern as destructive confirms elsewhere): `Reset? replaces
this file — ✓ / ✕` (mono 11px, `✓` in `#D9A03F`). Confirming rewrites
the file to the built-in default, reloads the buffer, chip flips to
`default`. Escape or `✕` cancels. No modal.

## Empty / edge states
- **No `veri/templates/` dir** (project scaffolded before this
  feature): every type shows `default`, editor shows built-in content,
  first save creates the directory and file.
- **Template file unreadable/binary**: editor shows the raw bytes
  best-effort with a warning strip (amber, per SRC-008's
  parse-degraded pattern): "This file couldn't be read as text."
- Templates never appear in the sidebar tree, search, or graph — they
  are not documents (DEC-023).

## State management
- `templates: { activeType, buffers: {type: string|null}, dirty:
  {type: bool}, confirmingReset: bool }` — session state, not
  persisted.
- Customized detection derives from core's `getTemplate` provenance +
  compare; never cached across saves or external changes.
- The Templates view is a view-tab key like `board`; one instance.

## Design tokens
No new tokens. Everything reuses `design/README.md` and the
markdown-editor / navigation-model bundles: backgrounds `#0F0F11` /
`#131316`, borders `#1E1E24` / `#1F1F24` / `#26262C`, text scale
`#E7E4DE` → `#55525E`, ember `#E8703A` / `#F0A87E`, warn `#D9A03F`,
type colors REQ `#7EA6C4` / DEC `#CFA83D` / WO `#E8703A` / SRC
`#908BA8`, fonts Source Sans 3 + JetBrains Mono.

## Explicitly deferred (do not build)
Template preview-as-rendered, per-type assembly-policy editing,
user-defined types, template version history, advisory conformance
indicators. Each waits for its own design/decision.
