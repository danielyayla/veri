A Veri project is a veri/ directory of readable Markdown. The files are the source of truth — the app is a view over them. Flip the toggle: same document, same bytes.

Four things operate on the same knowledge, and none of them owns it:

  • The Veri appreads and edits the files
  • Your editoropens them like any Markdown
  • Gitversions, diffs, and syncs them
  • Your agentretrieves them over MCP

Delete Veri and your project knowledge is still a folder of Markdown that renders on GitHub.

Why not a docs folder?

You already keep a CLAUDE.md. Maybe an ADR folder.

Good — that instinct is the whole idea. A CLAUDE.md tells your agent how to behave; an ADR folder remembers why. Veri is what they grow into when one growing file stops scaling. Four things a docs folder can't do:

Scoped retrieval

Each task gets the documents linked to it — a few thousand tokens, assembled fresh — not one ever-growing file pasted into every session whether it's relevant or not.

Typed links, linted

[[REQ-001]] is a reference veri check validates — broken links, work with no requirement, unapproved dependencies — the way a compiler validates code. A heading in a docs folder is just a heading.

The approval gate

Agent-filed decisions are proposals until you promote them. An ADR folder can't tell canon from suggestion once agents start writing into it.

Receipts

Finished work carries commit, files changed, and what was done — appended to the work order itself, with git provenance. Not a line in a chat log that scrolled away.

Scoped context

The agent gets a package, not a repo dump

The context package for a task is the documents linked to it — the project workflow, its requirements, every active decision within two hops, source excerpts. Typically a few thousand tokens, with a per-document estimate, assembled fresh from current file versions every time.

Superseded decisions ride along by name only, flagged as already rejected — so the agent doesn't relitigate them.

You see the exact package before the agent does, and start the session from it with one click. Click a document to see why it's in the package.

Human approval

Agents propose. You decide what becomes canon.

Agent-written requirements start as drafts, agent-filed decisions as proposals — labeled non-binding until you promote them. Nothing an agent writes silently becomes project truth. And when the work is done, it comes back as a receipt.

Get started

Start in ten minutes

1
Install Veri

The macOS app, or the CLI anywhere Node 20+ runs.

$ npm install -g @verikb/cli
2
Open the sample project

The app bundles a worked invoicing example — sixteen documents to read, edit, and break. On the CLI:

$ veri init --demo

Connect your agent
