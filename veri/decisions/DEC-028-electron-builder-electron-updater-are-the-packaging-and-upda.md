## Choice

packages/ui is packaged with electron-builder (config in electron-builder.yml) and updates itself with electron-updater in the main process. macOS ships a universal DMG (install) plus ZIP (Squirrel.Mac update artifact) with blockmaps for differential downloads. asar is disabled: the app writes the path of @veri/mcp's server.js into .mcp.json for agent clients to launch with plain node, and @veri/cli scaffolds from real demo files (DEC-007) — both need real files inside the installed bundle, which an asar archive cannot provide. The renderer's @codemirror/@lezer packages moved to devDependencies since DEC-021's esbuild bundle is the only way they ship, leaving the packaged node_modules at the four runtime deps (@veri/*, yaml, zod, MCP SDK, electron-updater). Electron is pinned exactly (electron-builder resolves platform binaries from the exact version).

## Rejected alternatives

- **Electron Forge + Squirrel.Mac directly** — first-party, but its update story needs a feed server (or update.electronjs.org) and has no differential downloads; frequent releases would cost users a full ~200MB each time.
- **update.electronjs.org** — free hosted feed, but macOS/Windows only, public-GitHub only, full-artifact downloads (no blockmaps), and adds a third-party service between users and releases for no capability gain over a static feed.
- **Custom update server** — maximum control (staged rollouts, channels), but standing infrastructure for a v1 need that a static feed meets; explicitly out of scope in WO-028.
- **asar with asarUnpack for @veri/**** — closer to electron-builder defaults, but ends up unpacking essentially all of node_modules (server.js's whole external-node dependency tree) plus the demo files; asar-in-name-only with extra failure modes.

## Rationale

electron-builder is the only mainstream packager whose companion updater (electron-updater) speaks a static-file feed with differential blockmap updates — no server to run, which matches the v1 no-infrastructure posture. Its metadata output (latest-mac.yml, blockmaps, app-update.yml) is generated by the same tool that builds the artifacts, so the feed can never drift from what was shipped. Universal binaries keep the feed to one artifact pair instead of per-arch downloads users must choose between.
